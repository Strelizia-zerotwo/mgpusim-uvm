# I-1 配置单（审查修复 v2）

主策略为 `i1`，与 INV 共用 `docs/INV-配置单.md` 中的全部平台、链路、缺页服务、映射准备和屏障设置。

| 行为 | 主 I-1 `i1` | 独立消融 `i1-write-prefetch` |
| --- | --- | --- |
| 冷的只读阶段 | 分配本地帧并复制整页 | 相同 |
| 普通只读阶段修复 | 仅复制将读取、且过期的子块 | 相同 |
| 写阶段已有副本 | 只有阶段开始前已有帧，且要读的子块已有效时，才允许本地读 | 相同 |
| 写阶段已有过期读取目标 | 回退 home；不在这一阶段提前修复 | 相同 |
| 写阶段从未有本地副本 | 回退 home | 允许新建副本，单独记账 |
| 写阶段与写集重叠/多写者页 | 整页该阶段回退 home | 相同 |
| 写入 | 访问 home；不写只读副本 | 相同 |
| 阶段结束 | 保留帧，累积所有写者 dirty 子块和版本 | 相同 |

主 I-1 因此是一个明确的、较保守的“已有有效副本继续读”方案。它没有把写阶段提前建立冷副本或修复已有过期副本的收益混入 S3。它不是任何机制都免费的全局数学上界。

两个变体的额外计数：

- `write_epoch_existing_replica_reads`：实际由阶段开始前已有副本服务的写阶段读取。
- `write_epoch_new_copies / write_epoch_new_copy_bytes / write_epoch_new_copy_faults`：写阶段新建副本及成本。
- `write_epoch_new_replica_reads`：写阶段由新建副本服务的读取。
- `s3_preexisting_replica_read_transactions`：以独立 INV shadow 计算的已有副本机会数，**不是实际本地服务数**。shadow 考虑容量驱逐，所有策略可报告相同机会。

`i1` 的写阶段新建副本、字节、缺页和读取四项必须为零，脚本自动检查。这个字段比仅看一个 S3 机会计数更能验证消融是否干净。

仍保留：精确 written mask、版本和子块有效性、源权威页真实数据复制、32/128/512/4096 B 传输取整及连续区间合并、正常计算和内存系统时间。元数据存储/维护、目录与 PTE 修改、TLB shootdown 免费；INV 同样免费。

逐级对照可以指定 `--policies inv,retain,i1-no-s3,i1,i1-write-prefetch`：retain 只保留帧和差量恢复；i1-no-s3 不在写阶段使用副本；主 i1 再开放已有有效副本；最后单独开放冷副本写预取。各项时间有交互，不能声称独立线性相加。

I-infinity 也受同样的冲突页 home 回退范围限制，并非整机无条件零成本。`i2` 仍只是参数化元数据/撤销成本预算，未实现真实记录硬件。GPS 更新与内核内权限缺页仍未实现。
