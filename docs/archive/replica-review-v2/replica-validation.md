严格 I-1 相对 INV 节省0.506us（约0.262%），但相对关闭 S3 的 i1-no-s3 **慢0.119us**。二者复制字节和固定服务次数相同；本组数据不支持“S3必然加速”或“S3主导收益”。内存访问路径与排队有交互，各消融差值不可当作相互独立的线性成本。

cold-write定向探针中，严格 I-1 的写阶段新副本/新副本字节/固定服务/新副本读四项均为0；i1-write-prefetch新增3个写阶段副本，由它们服务24次读。其总时间56.022us，比严格 I-1 的55.336us慢，开放冷预取并不保证加速。

fallback定向探针在最终代码上重新通过四种策略的数值、plan及公平性检查：1个多写者page-epoch、1个保守读写重叠page-epoch，均按页回退home，整个应用继续。它同时覆盖同页不重叠多写，以及实际字节不冲突但64B读事务引起保守重叠的情况。

probe的 `MemCopyD2D` 已核实：`driver/api.go` 加载 `copyKernel` 并调用 `EnqueueLaunchKernel`，在此模拟器中走GPU计算内核，不是DMA。

## 保留的建模假设

1. **home固定**：统一内存数据原始位置通常为GPU1；其他GPU写入也访问home，没有写时迁移。本INV是固定home+读复制。
2. **完美屏障预取**：复制/修复在阶段前按oracle完成，带宽和固定服务仍收费；kernel内不再承担动态复制缺页。INV同样享有免费目录、PTE安装和shootdown。
3. **公共全量缓存屏障**：每阶段所有策略都drain/flush/invalidate L1/L2并清TLB，计实际缓存屏障时间；会消除跨kernel L2复用并增大分母，尚未做按受影响页的精细失效。
4. **附加传播尚未标定**：0/100/200/500ns叠加在原有RDMA/缓存阶段之上；0不表示整个远端访问零延迟。传输预算为300GB/s，仍受1条/周期发送宽度与每方向128条有限在途窗口限制，不代表完整NVLink拓扑。
5. **复制数据路径限定**：功能上确实拷贝必要字节到物理副本，时序上支付共享fabric预算；尚未把每条复制DMA逐请求注入DRAM控制器。
6. **严格I-1不是普适数学上界**：它只允许写阶段继续使用已有且所需子块有效的副本；元数据免费，但冷预取与已有过期副本的写阶段修复被有意排除。i2仍为成本预算，未实现真实元数据缓存/溢出硬件。
