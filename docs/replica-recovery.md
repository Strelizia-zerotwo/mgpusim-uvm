# 失效副本低成本恢复：思路汇总

> 状态：候选设计，尚未验证。版本、dirty bitmap、差量恢复、子块有效位、惰性 shootdown 均有先例。

## 主线
利用 GPU 写入流，以有限成本维护版本和变化元数据，从权威页直接修复失效副本；不做整页比较，也不长期保存差量。
- 主要机制：写集捕获与版本管理
- 配套机制：按恢复完成时间合并传输区间
- 后续扩展：远端读还是本地修复

## 第一版限定（基线采用相同限定）
- 写阶段内每页只有一份权威数据，单写者
- 只在明确同步边界（kernel 边界）处理，程序无数据竞争
- 权威页稳定后才修复

## 元数据（两种实现，先比较，不急于选定）
1. 每个阶段一份 dirty bitmap，恢复时合并错过的阶段
2. 每个子块记录最后修改阶段，副本记录自己的版本，恢复时只取 last > version 的子块
   - 阶段号按页本地计数，回绕时强制整页恢复
- 示例：64 KiB 页、256 B 子块。bitmap 每阶段 32 B；16 位阶段号共 512 B（约 0.78%）

## 写集记录硬件
- 观察点：第一版限定下，可选在 home GPU 的 L2 入口（在 L1 合并之后、写回之前）。需先确认 akita-patched 中远端写确实经 RDMA 到达 home L2
- 小型元数据缓存，吸收同一子块的重复写；替换或阶段结束时写回；资源不足时保守地标记整页
- 只能多记不能少记；不能只监听缺页、TLB miss 或 DRAM 写回

## 推迟失效到同步边界（同一个设计选择带来的三类收益）
在 DRF 程序、只在 kernel 边界同步的前提下，写阶段内其他 GPU 不会合法地读正在被写的数据，所以失效可以推迟到边界：
1. 写阶段内，其他 GPU 继续本地读旧副本，不必退化成远端访问
2. 失效时写集已知，可以只失效脏子块（见下一节）
3. 不必在写阶段中途排空所有副本持有者的在途请求、等待 shootdown 确认；保留旧副本意味着帧不被重用，在途读访问旧帧仍然安全
- 不能省的：TLB 中的旧翻译必须在下一个同步点之前失效（逐项 shootdown，或在 kernel 边界整体刷 TLB）；本地 L2 中脏子块对应的行要作废，可以合并到修复写入中
- 例外：kernel 内跨 GPU 的 system-scope 同步，需要退回即时失效
- 先例：LRC write notice、LATR（ASPLOS'18，惰性 TLB shootdown）、IDYLL（MICRO'23，多 GPU 惰性 PTE 失效）、ShadowUpdate，待核实

## 子块有效性（大页内）
- 版本 v 之后未被写的子块可以直接读；失效消息携带脏掩码，副本把多次掩码累积 OR
- 检查位置：PTE 和 TLB 中的子块有效掩码（可查 sectortlb 的 subentries 能否复用）
- 访问到脏子块时：触发缺页并修复，或由硬件导向 home 远端访问
- 必须与"直接用 4KB 页"比较 TLB miss 和缺页次数
- 先例：subblock TLB（Talluri & Hill, ASPLOS'94）、Blizzard、Shasta、multiple-writer、CARVE、HMG

## 恢复模式（合并在一起）
干净子块立即可读 → 读到脏子块时修复或远端访问 → 脏子块太多时整页修复

## 必需的基线
- INV：整页重新复制
- 合理的 GPU twin/diff
- rsync 式校验和比较：不需要 twin，但两端都要读整页；涉及哈希碰撞问题
- GPS 式写更新、CDFD、单份远端访问、直接用 4KB 页

## 实验顺序
0. 先用离线分析器在规范的 benchmark 集上确认机会是否存在：再读率、脏子块比例、落后阶段数、复用读集与脏集的交集、推迟失效能省掉的远端访问和中途 shootdown 次数
1. GPU twin/diff 基线，拆分比较、生成、传输、权限恢复各自的时间
2. 免费精确写集的理想对照
3. bitmap 与"子块最后修改阶段"对比（重复写和元数据缓存可以先离线按写入顺序回放）
4. 有限资源模型
5. 传输合并
6. 完整应用的端到端时间

三条主曲线：GPU twin/diff、免费精确写集、有限资源写集记录。
停止条件：优势只出现在免费 dirty bitmap 的理想模型中。
