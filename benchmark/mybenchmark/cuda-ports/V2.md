# 独立的 -2 benchmark：原地更新与 GPU 分组

2026-10-23。新增 `SSSP-2、CC-2、COLOR-2、MIS-2、EMBEDDING-2`，原五项的 benchmark 代码、内核二进制、名字、输入和默认命令保留。新实现标签为 `cuda-derived-inplace-grouped-v2`，结果自动写入各自的 `results/benchmark/<名称-2>/<suite>/`。

新实现的复制协议仍是 `kernel-internal-ideal-v3`：每个真实请求在 AT 入口检查权限/版本，写立即失效，读触发复制或修复。没有 kernel 边界回放或免费梯度预处理。默认只跑 `inv,infinity`。

## 运行

```bash
cd /home/only/projects/mgpusim-uvm

# 仅检查命令；不构建、不启动模拟。
python3 runs/run_cuda_ports2.py --dry-run

# 建议先跑 COLOR-2、MIS-2。
python3 runs/run_cuda_ports2.py --bench COLOR-2,MIS-2

# 原地松弛及改进的稀疏训练算子。
python3 runs/run_cuda_ports2.py --bench SSSP-2,CC-2
python3 runs/run_cuda_ports2.py --bench EMBEDDING-2

# 五项全部依次执行，仍只比较 inv/infinity。
python3 runs/run_cuda_ports2.py

# 保持相同输入，扫描两个页大小。
python3 runs/run_cuda_ports2.py --page-bytes 4096,65536

# 新旧版本可以放进同一套件；分别计算各自相对 INV 的差距。
python3 runs/run_cuda_ports.py --bench COLOR,COLOR-2,MIS,MIS-2
```

默认四 GPU、CDNA3/MI300X、4 KiB 页、900 ns 固定服务、200 ns 链路延迟、300 GB/s，每个策略一次。默认每策略主机超时 86400 秒，可用 `--timeout 1800` 等覆盖。请依次跑套件，避免并发争抢主机资源。

输入与 v1 完全相同：图为 16384 节点、目标平均度 8，CC 为 4 个分量，其他为 1；Embedding 为 8192×32 FP32、全局 batch=128、8 批、相同 hotset 和 seed。此规模尚未证明具有大收益。更换页大小还会改变 home 放置与页内共享范围。

## 各项改变及边界

| 名称 | v2 行为 | 明确的边界 |
| --- | --- | --- |
| SSSP-2 | 一个顶点由一个线程写，遍历邻居时每次距离改善就立刻写回同一个 state；其他 GPU 在同一个 kernel 中也读写该 state | 是具有唯一写者的原地 pull，**不是来源的边并行 atomicMin 实现**；邻居扫描并行度、轮次与更新顺序可能不同 |
| CC-2 | 同上，逐次发布更小标签 | 同样不宣称精确移植 atomicMin；最终标签用 CPU CC 参考校验 |
| COLOR-2 | 在同一 kernel 中读邻居颜色、直接写本顶点；保留来源对本轮两种颜色的判断 | 仍全顶点调度，对已着色顶点早退，没有完整移植 Gunrock frontier/filter |
| MIS-2 | mark 读取邻居 state、原地写 MARKED；drop 从同一 state 读标记并写 NON_INDEPENDENT | 保留原有两个 kernel，没有为了交错而强行融合；仍全顶点调度及早退，没有完整 worklist |
| EMBEDDING-2 | lookup 后，由 GPU 在 LDS 中稳定 bitonic 分组索引，再由每个 run 的唯一线程组归并并更新该行 | 仍是单 ID FP32 平方误差 SGD 算子，不是完整 FBGEMM；当前全局 batch 必须为 **1–256** |

SSSP/CC 的正确性依据：每个顶点只有一个写线程，避免同一元素多个更新者之间的丢失更新；距离/标签只单调减小，所有策略都循环到没有更新，随后完整 CPU 校验。kernel 内的读取、普通 home 写和同步照常计时。没有把硬件原子操作伪装成普通 store，也没有为原子操作增加免费模拟器特例。

四个图应用的进度在 GPU workgroup 内归约，只回传每组一个 uint32。默认 16384 顶点有 64 组，因此每轮回传 256 B；归约的 LDS、barrier、普通写与 D2H 均实际执行并计时。SSSP/CC/COLOR 不再分配 proposal 和 N 元素 changed；MIS 使用原地 mark/drop 及同样的归约进度。

Embedding 分组是真正的 GPU kernel，固定一个 256 线程 workgroup，使用 LDS 排序 `(ID,原始位置)`；该分组阶段的执行、缓存和访存照常计时，其他阶段仍按统一 workgroup 规则分给四 GPU。排序后每行只归并自己的连续 run，不再让每个维度扫描整个 batch。排序稳定，因此同 ID 梯度按原样本顺序累加。CPU 只生成与 v1 一致的输入、检查结果，不排序 ID、计算梯度或更新权重。

这些选择恢复了关键的原地状态访问并降低了部分辅助工作，但未完整恢复来源框架的负载均衡、活动队列和 GPU 原子语义。因此不能把 v2 命名为来源程序的精确复现，也不承诺策略收益必然增大。必须结合新旧实现的轮次、kernel 数、复制次数、字节和应用时间判断。

## 输出与版本验证

沿用已有 REPORT、summary、copy-free-reference、原始日志、stats 和 progress 输出。`workload.json` 的 algorithm 包含 `-2`，另存 algorithm_family；implementation 与 catalog 必须匹配，否则结果标为验证失败。SSSP/CC/MIS 的收敛轮次可能因实现或执行时序不同而变化，实际值随结果保存。

独立代码：`mgpusim/amd/benchmarks/cudaports2/`。重新编译新内核使用：

```bash
python3 runs/build_cuda_ports2.py
```

旧版本仍使用 `runs/build_cuda_ports.py`；两个构建脚本输出不同目录。来源固定版本、许可证和原始快照继续使用本目录的 `SOURCES.json` 与 upstream 文件。

验证包括编译后内核的功能单元测试、正反 workgroup 顺序、同轮颜色依赖、逐次原地发布、尾部不足一组、稳定 ID 分组及多批梯度校验；脚本测试和构建另行记录。未由代理执行应用 timing、smoke 或性能实验。
