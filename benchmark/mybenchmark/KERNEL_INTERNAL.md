# Kernel 内理想收益实验：当前 INV / infinity 对照

当前版本：`kernel-internal-ideal-v3`，2026-10-17。以本文为当前实验口径。此前 v1/v2 的控制序列、缓存排队与实测数字属于历史实验。

## 比较的问题

在失效、权限、版本、目录、缓存维护和在途正确性处理均免费时，保留旧副本、下次只补变化的子块，能节省多少应用时间？

|策略|写请求|下一次远端 GPU 读|
|---|---|---|
|inv|立即使副本失效，释放逻辑帧|收一次固定服务费，复制整页|
|delta|立即使副本失效，保留帧和旧版本|收一次固定服务费，修复全部过期子块|
|delta-sub|保留帧和旧版本，记录各子块最后写版本|所需子块都干净则直接读；否则收一次固定服务费，仍修复全部过期子块|

2026-10-21起默认只跑 `inv,infinity`；delta/delta-sub 保留为显式选项。`infinity` 在实际 kernel 内读请求缺少副本或页版本过期时，同步功能复制/修复全部过期子块，恢复后直接放行；不增加 admission tick，不调度复制等待事件，不收 fault/链路延迟，不预留复制带宽，普通 GPU 执行仍计时。没有 adaptive、预取或未来访存分析。

“全部过期”指 `LastWrite[sector] > replica.Version`。子块为 32B。多次写积累到下次读时合并为一次修复；同一子块重复写只传最新快照。帧已回收时退回整页复制。全部子块都过期时，差量字节数自然等于整页，不额外收合并、分段或包头费用。

## 触发和并发

在地址转换器 AT 入口检查每个实际请求，位于翻译与数据缓存之前；TLB 命中也检查。

写请求零时间增加 home 版本，更新被写子块的版本并立即失效副本。普通写数据路径继续运行，不发 Drain/Flush/Invalidate/Enable 消息，不排空全机，不等待副本读结束。

读缺副本或需要修复时，仅该请求及合并到同次服务的请求等待。AT 把等待项移出入口 FIFO，允许后面的其他页继续翻译。同一页、同一读者 GPU、同一 home 版本的等待读合并。不同页可并发，没有全局单转换锁，也没有每 GPU 单修复队列。实际 AT/缓存端口和链路带宽仍有普通资源竞争。

固定服务 `fault_ns` 结束时才向共享 fabric 预留总字节传输；等待固定服务时不提前占住未来链路。不同、不相交的发送/接收 GPU 对可重叠；共用源或目的 GPU 的数据传输按带宽竞争。

不使用 kernel 结束后的访问摘要来决定复制。kernel 序号只标记事件；边界处仅把功能结果物化给主机校验，不修改版本、有效性或修复选择。

## 哪些时间收费

|项目|三策略统一口径|
|---|---|
|权限、失效、TLB shootdown、元数据、目录查询|免费且立即生效|
|home L2 脏行发布、读者缓存作废、在途数据转发|零时间功能操作|
|kernel 启动的公共数据 L1 维护、kernel 后主机校验物化|免费，无缓存控制消息|
|每次复制/修复的固定服务|一次 `fault_ns`|
|复制/修复数据|一次总字节带宽费用及链路附加延迟，无 extent/header 费用|
|普通计算、翻译命中、缓存访问、DRAM、常规 RDMA|继续使用模拟器时序；各策略统一|

孤立且无竞争的一次服务为 `fault_ns + link_ns + ceil(bytes * 1000 / bandwidth_GBs) / 1000` 纳秒。GB/s 使用十进制；带宽为 0 表示无限带宽，附加延迟仍收取。复制和普通远端流量共享 Fabric。

所有策略免费预装映射，无映射缺页。`fault_slots`、传输粒度与系统级同步注解是历史配置字段；ideal-v3 不用它们限制复制队列、合并区间或制造冲突页回退。脚本把同步注解置为 false。本实验不增加硬件原子/系统级同步支持。

## 免费正确性怎样实现

直接操作 Akita 缓存目录的辅助函数按物理地址发布 home L2 脏字节、作废副本帧缓存行。它们保留锁、读计数和已经发出的事务，不推进模拟时间，不生成缓存消息。

仅修改缓存标签不足以处理正在返回的旧数据，因此理想功能层另维护精确的权威页内容。写在 AT 接纳时立即更新权威内容；读在首次检查时保存当时的字节快照与版本，在正常后端访存完成时返回该快照。等待复制期间的写会立刻影响后续读，原读仍返回自己开始时的数据。旧修复完成不能覆盖新版本，旧物理写完成不能覆盖更新后的功能值。这里的“快照”只使用当时已经到达的请求，没有未来信息。

这是理想在途转发的功能假设，不能作为真实缓存一致性实现的证据。`functional_read_corrections` 显示功能层替换后端不同读值的次数；它可能非零。`stale_read_sectors` 检查被判定可读的副本帧是否包含过期字节，必须为零，发现即报错。应用还必须通过原 benchmark 数值验证；这两种检查含义不同。

INV 写时立即释放策略可见的帧。有后端读尚未结束时，物理地址暂不重用，以免破坏普通缓存事务；这只是免费功能记账，不阻塞失效或其他请求。该额外暂留另报 `peak_backend_pinned_frames`，与方案的保留旧帧分开。有限容量时它仍可能暂占物理分配器空间，建议第一轮使用默认不限逻辑副本帧预算，并检查 fallback 指标。

## 结果字段

- `application_us`：模拟应用总时间；等于 kernel、host transfer 等解释项之和。初始输入上传在首个 kernel 计时窗口之前。
- `kernel_us`：实际 kernel 时间，已包含其中等待复制/修复的影响。
- `wall_s`：宿主机实际运行秒数，与模拟应用时间不同。
- `cold_copies / refills / repairs / copy_faults`：首次整页复制、INV 整页重复制、delta 修复、全部服务次数。
- `copy_bytes / charged_bytes`：实际复制/修复的功能字节数、收费字节数。INV/delta/delta-sub 两者相等；infinity 的 copy_bytes 仍记录功能操作字节，charged_bytes 为零。
- `invalidations`：已完整有效副本变为过期的次数；已过期后的多次写不重复计同一次失效。
- `intrakernel_refills / intrakernel_repairs`：同一 kernel 标签内发生再次复制/修复的次数。
- `clean_replica_reads_during_write`：页已过期但所需子块干净而免修复的读次数，对应 delta-sub 扩展。
- `peak_replica_bytes`：所有策略的逻辑副本峰值；`peak_retained_frames/bytes` 为 delta 保留帧峰值，`peak_stale_retained_frames/bytes` 为其中过期旧副本的峰值。INV 的保留旧帧计数为零。
- `in_kernel_copy_service_us`：所有并发复制服务延迟之和，含等待链路；不能再加到 application_us。
- `barrier_us / recovery_us / in_kernel_cache_control_us`：ideal-v3 均应为零。

完整事件时间、快照版本、页、GPU 与字节在 `stats.json` 的 `passive.events`。结果摘要会检查三策略的输入摘要与 home 放置一致，确认四卡实际执行，并排除失败/超时。

## 合理性与结论边界

同一事件序列、同一孤立修复上，delta 传输字节不超过 INV，infinity 的复制服务为零。单元测试覆盖 3 页大小 × 2 固定开销 × 2 附加延迟。

应用时间也应重点检查上述排序，但异步调度可能改变到达顺序、合并次数、失效次数和缓存状态，因此单次服务的排序不构成整个应用绝对单调的证明。脚本保留原始应用时间；delta 比 INV 慢或infinity 比 INV 慢时标记 sanity_warnings，检查事件而不修饰结果。

本轮只执行构建和测试，未执行 smoke、microbenchmark 或核心应用；尚无 ideal-v3 的实测收益和应用数值验证结论。用户自行运行后再判断。

补充应用也支持 CDNA3/MI300X；主机物化功能结果时会免费清除相关内存侧 MALL 旧行，防止 DMA 校验读取旧内容。显式实验页大小覆盖 MI300X 默认2MB。见 [IDEA_CANDIDATES.md](IDEA_CANDIDATES.md)。
